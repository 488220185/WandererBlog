## Supabase 迁移实战：踩了 5 个坑，全部已解决

用户从 WorkBuddy 后端迁到 Supabase（为绑自有域名），建表 + 数据导入已全部完成。

### 遇到的报错与解法（按时间顺序）

**1. `42P01: relation "posts" does not exist`**
执行顺序错了：`rls.sql` 里的 `CREATE POLICY ... ON posts` 要求表先存在。
解法：先跑 `schema.sql` 再跑 `rls.sql`。三个脚本都有 IF NOT EXISTS / DROP POLICY IF EXISTS，可重复执行。

**2. `22P02: invalid input syntax for type uuid: ""`**
脚本按 WorkBuddy 行为写的（`auth.uid()` 返回 text），但 Supabase 的 `auth.uid()` 是 **uuid 类型**，
与 `''` 比较直接类型转换失败。
解法：凡与字符串比较一律先 `::text`。`IS NOT NULL` 不需要加（NULL 判断不涉及类型转换）。

**3. `42703: column "row_security" does not exist`**
PostgreSQL 19 把 `pg_tables.row_security` 改名为 `rowsecurity`。
解法：改用底层系统表 `pg_class.relrowsecurity`，跨版本稳定。

**4. `23502: null value in column "owner_id"`（跑两次）**
SQL Editor 无登录态，`auth.uid()` 返回 NULL，撞上 NOT NULL。
第一次是测试脚本没显式给 owner_id；第二次是 seed.sql 忘了加这个字段。
解法：seed.sql 每条显式填 `'system'` 占位，并加 `ON CONFLICT (slug) DO NOTHING` 保证幂等。
（正式登录用户发文时 owner_id 仍由数据库自动填真实 uid，不受影响。）

**5. PowerShell 环境问题（连着 4 个）**
- `npm` 找不到 → Node 只装在 WorkBuddy 内部目录，未进系统 PATH
- `npm : 无法加载 npm.ps1` → PowerShell 执行策略禁止脚本，改用 `npm.cmd` 或 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
- `ByteString character index 10` → 密钥里混进了中文占位符「你的密钥」
- `getaddrinfo ENOTFOUND xn--ref-x69di30p.supabase.co` → URL 里还是占位符「你的ref」，被 PunyCode 编码

**教训：给用户的示例命令里带中文占位符（你的密钥/你的ref）极易被原样执行。**
后续给命令时应显著标注"必须替换"，或提供填写表单。
